## Цель (продуктовая)

Органическая конверсия страницы Google Play оказалась ниже публичного ориентира, а основная потеря идёт на шаге «показ в Explore → визит страницы». Действующие скриншоты описывают интерфейс v1. Кадр с пэйволом нарушает политику графических ассетов Play: на нём цены, «free trial» и скидка. Новый набор из 8 phone-скриншотов и feature graphic собирается из настоящих экранов 1.21.0, чтобы листинг больше не отставал от приложения. Цифры замера лежат в gitignored `docs/marketing/` (не проверено — каталог в git не отслеживается) и сюда не попадают.

## Технический план

1. Разбор конверсии: @google-play-console-expert (GCS-экспорт через SA) + чтение Play Console → @marketing-expert (вердикт, бриф кадров).
2. @design-expert — DESIGN_SPEC 8 кадров + feature graphic, проверенный HTML-прототипом.
3. Эксперимент со страницей en-US «2» остановлен 2026-09-15, варианты не применены. Владелец отправил остановку на ревью в тот же день.
4. @compose-expert — Roborazzi-тест в `composeApp/src/androidHostTest`: реальные composable 1.21.0 на фейковых состояниях, компоновка кадра (фон, заголовок, корпус телефона) в тестовом коде, экспорт без альфа-канала.
5. Seams без изменения поведения (решение владельца после итерации 4), по факту реализации:
   - публичный `AnalyzeScreenContent(screenState, onIntent)`: `AnalyzeScreen` передаёт в него `viewModel::sendIntent`, `AnalyzeContent` остался закрытым и зовётся изнутри;
   - stateless перегрузка `TemplatesScreen(state, onIntent, useProjectTitle, onCreateWithAi)`, в которую делегирует VM-вариант;
   - публичная перегрузка `ChecklistDetailContent` без типов док-панели, делегирует в единственную закрытую реализацию. Прод-путь по-прежнему вызывает закрытую реализацию напрямую. Отдельный вход для `WeeklyChecklistDetailContent` не понадобился: недельный режим рисуется внутри той же реализации;
   - необязательный `weeklyTodayWeekday` (по умолчанию `null` = часы устройства) — единственная ветка сверх сигнатур, принята сознательно ради детерминированного кадра. Причина: из `composeApp` не видны `internal`/`private` Content-функции фич, а без них не снять кадры 2, 3, 4, 6, 7.
6. Владелец заливает кадры и текстовые правки листинга одной отправкой на ревью. Замер — CTR страницы до и после, в окне без рекламы (Google Ads выключен владельцем).

## Выводы

- Набор из 8 phone-скриншотов и feature graphic генерирует `StoreListingFramesScreenshotTest` из реальных экранов 1.21.0. Все файлы RGB без альфа-канала, проверка стоит внутри теста. Постоянный документ: `docs/solutions/ui-improvements/store-listing-frames-from-real-composables-2026-09-15.md`.
- Первый заход дал 3 кадра из 8: Content-функции Analyze, шаблонов и детального экрана закрыты (`internal`/`private`). Владелец одобрил seams без изменения поведения, после них собраны все кадры. Тесты analyze/create/home и debug-сборка `androidApp` зелёные, источник: прогон Gradle в этой сессии.
- Спека разошлась с реальным 1.21.0, выиграл реальный UI:
  - чат из вкладки открывается панелью поверх навигации, поэтому кадр 1 — полноэкранный маршрут;
  - в строке ввода чата нет тоггла «Важное»;
  - в Inbox нет чипов проектов;
  - в центре нижней навигации кнопка AI;
  - недельный режим — секции, а не селектор дней.
- Через API Play не видно ни экспериментов со страницей, ни разбивки Search/Explore. Эксперимент «2» остановлен вручную в консоли, отправку на ревью сделал владелец.
- Осталось за владельцем: загрузить кадры и текстовые правки листинга одной отправкой на ревью, записать дату D для замера CTR. Правки текста перечислены в `docs/todos/2026-08-18-store-listing-v2-drift.md` (не проверено: файл лежит только в основном checkout и в git не отслеживается). Иконка — следующим отдельным окном.
