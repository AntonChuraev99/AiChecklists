# `.claude/skills/` остаётся вне git

## Контекст

Задача 2026-08-18 открыла `docs/` и `.claude/rules|hooks` в публичный репозиторий (ADR
`docs/decisions/2026-08-18-docs-published-by-whitelist.md`). Владелец выбрал открыть и
`.claude/skills/`. При проверке содержимого перед публикацией это отменено.

## Почему отменено

`.claude/skills/ai-chat-feedback-fixer/processed-feedback.md` — таблица разобранных
thumbs-down из AI-чата, где колонка `question` содержит **дословные сообщения реальных
пользователей**, выгруженные из аналитики: личные списки дел, имена файлов-вложений,
текст на других языках, бытовые подробности. Это чужие персональные данные.

Класс проблемы иной, чем у остального в этой задаче. Гейт `scripts/docs_leak_scan.py` ищет
цифры, идентификаторы и креды — он такую строку не поймает и не должен: там нет ни числа,
ни ключа, только чужой текст. Никакая настройка regex этого не закрывает.

Побочно в `skills/` лежат id проекта Amplitude и адрес деплой-аккаунта в примерах команд —
это гейт как раз ловит, но чинить их отдельно бессмысленно, пока не решён главный вопрос.

## Что нужно сделать

1. Решить с владельцем судьбу `processed-feedback.md`: (а) вынести в gitignored-файл рядом
   и оставить в скилле только обезличенные категории сбоя; (б) заменить цитаты на
   перефразированные описания; (в) оставить как есть и не публиковать скиллы никогда.
2. Выбран (а) или (б) → прогнать `python scripts/docs_leak_scan.py .claude/skills` и снять
   оставшиеся находки (Amplitude id, адреса аккаунтов в примерах `gcloud`).
3. Открыть в `.gitignore`: строка `!.claude/skills/` рядом с существующими
   `!.claude/rules/` и `!.claude/hooks/`, где сейчас стоит объясняющий комментарий.

## Чем это мешает сейчас

Ничем срочным. `.worktreeinclude` копирует скиллы в новый worktree, так что работа
не блокируется — в отличие от `.claude/rules/`, ради которого задача и затевалась
(целая ветка `feat/ux-overhaul` шла с нулём файлов правил).
