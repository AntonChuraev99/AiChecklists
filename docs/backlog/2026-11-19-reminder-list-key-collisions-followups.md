# Ревью vc92: три кандидата того же класса, что FATAL дубля ключа

## Откуда

Релиз vc92 / 1.23.1 (PR #75, `cdb3285b`) чинил FATAL `Key "cl_…" was already used` на экране Today:
разовое напоминание и повтор в тот же момент давали две строки с одинаковым ключом. Ключ строки
собирается из неполного набора полей — `"cl_${checklistId}_${reminderAt}"`
(`feature/home/.../today/TodayViewModel.kt:551`). Фикс отбрасывает разовое напоминание в
`buildRemindersInRange`; после выхода vc92 краш больше не появлялся.

Ревью того же PR оставило три находки, которые в релиз сознательно не вошли.

## Находки (из заметок ревью; в коде проверена только первая часть пункта 1)

1. **Правило повтора с `interval = 0`.** Быстрая перемотка для простых интервалов падает на
   `require(intervalMillis > 0)` (`feature/checklist/.../domain/model/ReminderRepeatRule.kt:269`) —
   `IllegalArgumentException`. По заметке ревью, `expandInRange` на том же правиле плодит дубли
   вхождений. Неизвестно, может ли такое правило вообще появиться — из UI, от AI-агента или из синка.
2. **Дубли `itemId` внутри одного заполнения** — по заметке ревью; источник не установлен.
3. **Ключ строк Calendar без `fillId`.** Два заполнения одного чек-листа на одно и то же время дадут
   одинаковый ключ, то есть тот же FATAL, что чинили в vc92. Место сборки ключа в этой сессии не искали.

## План

1. По каждому пункту сначала доказать достижимость: найти путь, которым такое состояние создаётся
   (UI, `ToolCallDispatcher` агента, входящий синк). Недостижимое — закрыть с объяснением.
2. Достижимое — багфикс по проектному протоколу: red-репро на точку поломки до фикса, фикс слоя-корня
   (ключ из полного набора полей, валидация `interval >= 1` на входе правила), зелёный прогон
   `./gradlew :feature:home:testAndroidHostTest :feature:checklist:testAndroidHostTest`.
3. Соседи: проверить все `LazyColumn`/`items(key = …)` списков напоминаний на тот же паттерн неполного ключа.
