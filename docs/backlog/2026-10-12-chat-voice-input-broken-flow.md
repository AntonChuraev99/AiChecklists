Диагностика 2026-10-12 на эмуляторе (debug-сборка текущего `master`, свежая установка, вход с
главного экрана через нижнюю панель чата). Сама запись и распознавание работают: сервер вернул
текст, он попал в поле ввода. Но для пользователя сценарий выглядит как «ничего не произошло».
Чинить все четыре пункта одной задачей — по отдельности они маскируют друг друга.

## Что сломано

### 1. Запись стартует дважды на одно нажатие

Жест нажатия вызывает `start()` рекордера напрямую и одновременно шлёт
`ChatScreenIntent.OnVoiceRecordingStarted`. ViewModel в ответ эмитит
`ChatScreenSideEffect.RequestRecordAudioPermission`, а обработчик этого эффекта вызывает
`start()` ещё раз.

- Панель на главной: `App.kt` — обработчик эффекта (`sheetAudioRecorder.start()`) и оба
  `onVoiceRecordingStarted = { sendIntent(...); sheetAudioRecorder.start() }`.
- Полноэкранный чат: `ChatRoute.kt` — обработчик эффекта (`audioRecorder.start()`) и
  `onVoiceRecordingStarted = { audioRecorder.start() }`; интент при этом шлёт `ChatScreen.kt`.

Второй вызов не безвреден: `startRecording()` в `AudioRecorder.android.kt` освобождает
предыдущий `MediaRecorder` и удаляет его файл. Системный журнал звука на эмуляторе показал две
сессии микрофона на одно удержание: первая обрывается почти сразу, в файл попадает только хвост.

Направление фикса: один владелец вызова `start()`. Либо жест, либо обработчик эффекта — не оба.
Проверить на устройстве, что файл содержит всю запись.

### 2. Панель чата на главной исчезает во время записи и не возвращается

При старте записи поле ввода отключается, клавиатура закрывается, панель сворачивается. В
текущем нижнем хроме свёрнутое состояние не показывает ни поля ввода, ни индикатора: на экране
обычная главная. После отпускания панель не раскрывается, индикатора «распознаю» не видно,
распознанный текст попадает в поле ввода закрытой панели.

Направление фикса: на время записи и распознавания панель остаётся видимой (или раскрывается
обратно по приходу результата). Это вёрстка и состояние панели — зона `@compose-expert`,
скриншот-цикл обязателен.

### 3. Первое нажатие после установки всегда теряется

Системный запрос разрешения на микрофон обрывает жест. Пользователь видит только «запись
отменена» и подсказки нет — нужно догадаться нажать и удерживать заново. При этом по коду
рекордера (`AudioRecorder.android.kt`) запись после выдачи разрешения всё-таки стартовала — без
удерживаемого пальца и без индикатора: признак ожидания старта переживал отмену жеста.

Направление фикса: после выдачи разрешения показать подсказку «удерживайте, чтобы записать»;
не считать этот случай отменой в аналитике.

### 4. Причина «отмены» не измеряется

`onResult(null)` («отменил или слишком коротко») и `onError` (отказ в разрешении, ошибка
железа, слишком короткая запись — `MediaRecorder.stop()` бросает исключение) уходят одним
`OnVoiceRecordingStopped(recordingPath = null)` → одно событие отмены без причины. Добавить
параметр причины, иначе следующий замер снова не отличит поломку от поведения.

## Отдельно: холодный старт функции распознавания

Ответ `transcribe_audio` на первом вызове шёл десятки секунд (холодный инстанс). Лечится
минимальным числом инстансов у функции — это постоянная плата, решение владельца. Без него
после фикса клиентских дефектов человек всё равно будет долго ждать первый результат; минимум —
держать видимый индикатор распознавания.

## Чего проверка не доказала

Эмулятор пишет тишину с микрофона хоста и заметно тормозит, поэтому доля потерянной записи на
реальном телефоне может быть другой. Двойной старт и исчезающая панель от эмулятора не зависят.
Перед фиксом — репро на физическом устройстве с логом звуковых сессий.
